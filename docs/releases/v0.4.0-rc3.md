## Included Software Changes

- Added a default-off Grasshopper `Diagnostic LBM Nu Override` input and manifest field for reproducing `nu_lbm` sensitivity studies without changing CityLBM defaults.
- Added native Case E generator controls for effective-ground, domain decomposition, and `nu_lbm` diagnostics.
- Improved Case E audit tooling so solid-corner risk metadata is propagated into residuals, group metrics, XLSX output, and the validation report.
- Fixed the release-gate recommended-tag logic for existing rc tags.

## Default vs Experimental

Default-safe:

- Build-chain fallback and manifest/audit reporting.
- Fail-closed release gate.
- Solid-corner risk reporting.

Preset-only:

- AIJ Case E `ac+N` constants, AF profile scaling, official z=2 m probe target.

Experimental only:

- wind-direction audit (`+Y` vs `-Y`);
- no-SUBGRID diagnostic run;
- sample interval changes for CPU-side probe extraction;
- near-wall, rough-wall, effective-ground, `nu_lbm`, and alternative probe sampling modes.

## Manuscript Use

Paper-ready:

- Dataset provenance, hashes, and official 80-probe z=2 m protocol.
- Reproducible build/runtime evidence for the current machine.
- Negative diagnostic finding: the current CityLBM/FluidX3D Case E pipeline does not yet meet official z=2 m accuracy requirements.
- Solid-corner diagnostic as a limitation/protocol-risk analysis.

Limitations only:

- Current Case E accuracy metrics.
- Directional improvement from effective-ground and lower `nu_lbm` diagnostics; it is not enough for a formal validation claim.
- Any claim of predictive accuracy, mesh independence, LES improvement, or validated v0.4.0 performance.

## Release Gate

Formal `v0.4.0` must not be tagged until the official z=2 m metric gate passes, Rhino/Grasshopper loads the new GHA, and Case A smoke regression is verified.
