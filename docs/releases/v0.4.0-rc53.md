# CityLBM v0.4.0-rc53

## Manifest-level publication-readiness contract

This release candidate feeds the Case E publication-readiness audit back into
the CityLBM plugin itself. Generated `citylbm_run_manifest.json` files now
include a `publication_readiness_contract` section.

The contract records that a generated case manifest is protocol and software
traceability only, and that manuscript use requires external evidence gates:

- `casee_publication_readiness_gate.json`
- `casee_claim_support_gate.json`
- `casee_solver_run_provenance_ledger.json`
- paper figure QA
- the reproducibility suite

It also records allowed publication roles and forbidden publication claims,
including formal accuracy from the manifest alone, predictive accuracy, mesh
independence, LES improvement, diagnostic candidates as formal results, and
post-hoc calibration as validation.

Updated gates:

- `citylbm_manifest_output_gate.py`
- `citylbm_manifest_schema_gate.py`
- `citylbm_software_feedback_matrix.py` as SF031
- `casee_publication_readiness_gate.py`

## Boundary

This is a software traceability and claim-boundary enhancement only. It does
not add a new FluidX3D run, change solver defaults, improve official z=2 m
metrics, or permit a formal `v0.4.0` release.

Formal Case E official z=2 m metrics remain:

- MAE = 21.111 pp
- R2 = -2.006330
- Pearson = 0.115756

Formal `v0.4.0` remains blocked until the official z=2 m metric gate and
Rhino/Grasshopper new-GHA loading gate pass.
