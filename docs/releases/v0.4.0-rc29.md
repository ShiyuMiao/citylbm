# CityLBM v0.4.0-rc29

## Status

CityLBM `v0.4.0-rc29` is an accuracy-diagnostic and manifest-gate release candidate. Formal `v0.4.0` remains blocked.

## Added

- Generated `citylbm_run_manifest.json` files now include `formal_accuracy_gate`.
- `citylbm_manifest_output_gate.py` verifies the manifest accuracy-gate contract.
- `casee_default_policy_gate.py` verifies that the new contract does not promote diagnostic settings into defaults.
- `citylbm_software_feedback_matrix.py` adds SF012 for the manifest-gate software traceability layer.

## Manifest Contract

The new `formal_accuracy_gate` records:

- release target: `v0.4.0`
- official Case E condition: `ac`
- official wind direction: `N`
- required wind vector convention: `(0, -1, 0)`
- formal validation height: z = 2 m
- required probe count: 80
- required formal sampling: `raw_trilinear`
- required external release gate: `release_gate.json`
- required Case A smoke regression
- required Rhino/Grasshopper new-GHA load verification
- required metric trend: MAE clearly below the previous near-20 pp level, R2 positive, Pearson positive
- diagnostic substitutes disallowed as formal evidence

## Evidence Boundary

This release candidate improves run-level traceability and misuse prevention. The manifest is protocol evidence only; it cannot authorize a formal accuracy claim without external official z=2 m metrics from completed Case E runs.

## Not Allowed
