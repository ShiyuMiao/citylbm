# CityLBM v0.4.0-rc64

## Scope

This release candidate adds a GPU runtime fail-fast gate for long native
FluidX3D Case E scheduling.

## Added

- `docs/experiments/casee/tools/citylbm_gpu_runtime_failfast_gate.py`
- `docs/experiments/casee/results/citylbm_gpu_runtime_failfast_gate.json`
- `docs/experiments/casee/results/citylbm_gpu_runtime_failfast_gate.csv`
- `docs/experiments/casee/results/citylbm_gpu_runtime_failfast_gate.md`

## Evidence

The gate runs `nvidia-smi` and records whether long FluidX3D runs are allowed.
On the current workstation it correctly records `gpu_runtime_ready=false` and
`long_fluidx3d_run_allowed=false` because the device reports `GPU is lost`.

## Boundary

This is runtime safety and reproducibility evidence only. It does not recover
GPU runtime, run FluidX3D, change solver defaults, improve official z=2 m
metrics, or permit a formal `v0.4.0` release. Formal `v0.4.0` remains blocked
by the official z=2 m metric gate, missing Rhino/GHA load evidence, GPU runtime
recovery, and unresolved VS C++ Build Tools blockers.

Current official Case E z=2 m metric remains MAE = 21.111 pp, R2 = -2.006330,
Pearson = 0.115756.
