# CityLBM v0.4.0-rc1 Release Notes

Status: accuracy diagnostic release candidate. This is not a formal v0.4.0 release.

## Newly Run Evidence

- CityLBM build: passed with local .NET SDK 8.0.423, 0 errors with existing nullable warnings; see `docs/experiments/casee/results/citylbm_build_check.log`.
- Native FluidX3D runtime: executable recorded and runnable; the latest `nvidia-smi` audit reports one lost GPU handle, so multi-GPU availability remains an environment risk.
- Native Case E dx=3 m and dx=2 m runs completed at official z=2 m; see `docs/experiments/casee/results/casee_native_metric_comparison.csv`.
- Effective-ground and `nu_lbm` diagnostics completed; see `docs/experiments/casee/results/casee_ground_nu_diagnostic_comparison.csv`.

Best official z=2 m result so far:

- Run: `dx2_gshift1_nu001`
- n = 80 official `ac+N` probes
- MAE = 23.972 percentage points
- RMSE = 29.095 percentage points
- Bias = -20.833 percentage points
- R2 = -2.311768
- Pearson = 0.071789

## Included Software Changes

- Added native Case E generation tooling with AF_caseE profile scaling, official probe embedding, binary STL conversion, and direct probe time-mean CSV output.
- Added a default-off Grasshopper `Diagnostic LBM Nu Override` input and manifest field for reproducing `nu_lbm` sensitivity studies without changing CityLBM defaults.
- Added MinGW/g++ fallback compilation for FluidX3D when MSBuild is missing or fails.
- Improved Case E audit tooling so local tool paths, generated GHA hashes, FluidX3D executable hashes, run matrix state, and release target are recorded explicitly.

## Default vs Experimental

Default-safe:

- Build-chain fallback and manifest/audit reporting.
- Fail-closed release gate.

Preset-only:

- AIJ Case E `ac+N` constants, AF profile scaling, official z=2 m probe target.

Experimental only:

- wind-direction audit (`+Y` vs `-Y`);
- no-SUBGRID diagnostic run;
- sample interval changes for CPU-side probe extraction;
- near-wall, rough-wall, effective-ground, `nu_lbm`, and alternative probe sampling modes. The CityLBM `nuLBM` input is an explicit diagnostic override, not a validation default.

## Manuscript Use

Paper-ready:

- Dataset provenance, hashes, and official 80-probe z=2 m protocol.
- Reproducible build/runtime evidence for the current machine.
- Negative diagnostic finding: the current CityLBM/FluidX3D Case E pipeline does not yet meet official z=2 m accuracy requirements.

Limitations only:

- Current Case E accuracy metrics.
- Directional improvement from effective-ground and lower `nu_lbm` diagnostics; it is not enough for a formal validation claim.
- Solid-corner and affine-calibration diagnostics from `casee_nu001_error_diagnostics.csv`.
- Any claim of predictive accuracy, mesh independence, LES improvement, or validated v0.4.0 performance.
- Diagnostic sampling or height offsets as substitutes for official z=2 m validation.

## Release Gate

Formal `v0.4.0` must not be tagged until the official z=2 m metric gate passes, Rhino/Grasshopper loads the new GHA, and Case A smoke regression is verified.
