# CityLBM v0.4.0-rc34

Release type: accuracy-diagnostic release candidate.

CityLBM `v0.4.0-rc34` adds default-off wall and roughness follow-up controls for the AIJ Case E near-wall limitation workflow. Formal `v0.4.0` remains blocked.

## Added Or Updated

- `Diagnostic Wall Model` (`wallModel`) Grasshopper input on `Run Simulation`, default `none`
- `Diagnostic Roughness Length` (`z0Wall`) Grasshopper input on `Run Simulation`, default `0.0 m`
- `SimulationSettings.DiagnosticWallModel`
- `SimulationSettings.DiagnosticRoughnessLengthM`
- Generated `setup.cpp` audit constants for wall/roughness follow-up settings
- `citylbm_run_manifest.json` fields blocking wall/roughness diagnostics as default accuracy models
- Default-policy gate checks for wall/roughness default-off status
- Manifest-output gate checks for wall/roughness claim-boundary fields
- Software-feedback matrix row `SF017`

## Wall And Roughness Boundary

The new inputs are traceability controls for future near-wall follow-up experiments. They do not change CityLBM's default wall treatment when left at their defaults. Non-default values are diagnostic-only until a completed official AIJ Case E `ac+N` z=2 m raw-trilinear run shows stable metric improvement and the release gate passes.

## Boundary

This release candidate improves controlled follow-up interfaces and reviewer traceability only. It does not add CFD results, improve the official AIJ Case E z=2 m metric, prove mesh independence, prove Rhino loaded the new GHA, promote wall/roughness diagnostics to formal validation, or permit a formal `v0.4.0` tag.
