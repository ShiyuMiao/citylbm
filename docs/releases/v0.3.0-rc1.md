# CityLBM v0.3.0-rc1 Release Notes

Status: accuracy diagnostic release candidate. This is not a formal v0.3.0 release.

## Why This Is an RC

The formal v0.3.0 gate requires a successful CityLBM build, Rhino/Grasshopper loading of the new GHA, native FluidX3D dx=3 m and dx=2 m official z=2 m runs, positive R2, positive Pearson correlation, clearly improved MAE, and Case A smoke regression. The current machine lacks a .NET SDK, MSBuild, FluidX3D executable/source build, CUDA/NVIDIA runtime evidence, and native run logs. Therefore the formal tag `v0.3.0` must not be created.

## Included Improvements

- AIJ Case E `ac+N` preset with scale factor, Uref, zref, wind vector, official geometry, and 80-probe filter.
- Zenodo data manifest with file sizes, SHA256, Zenodo MD5, source URL, and download timestamp.
- AF_caseE inlet profile audit table and figure generation.
- Probe residual and metrics pipeline for official z=2 m only.
- Release gate that fails closed unless all formal v0.3.0 criteria pass.
- Evidence inventory separating `newly_run`, `preexisting_artifact`, and `user_claim`.
- Source-level plugin changes: explicit `AIJ Case E Preset` input, `SimulationProtocolPolicy`, AF_caseE inlet-profile generation, lattice velocity cap scaling, and `citylbm_run_manifest.json` output.

## Default vs Experimental

Default-ready:

- Case E preset constants.
- Official `RS_caseE.csv` filtering for `case=ac`, `Wind_direction=N`, `z=2 m`.
- Raw trilinear sampling as the formal validation mode.
- Release-gate checks that prevent formal publication without evidence.

Experimental switches only:

- `nearest_valid`.
- `fluid_weighted`.
- `vertical_valid_above`.
- `z_plus_half`.
- near-wall, rough-wall, and effective-ground diagnostics.
- full-plane digital-filter inlet until native FluidX3D improvement is demonstrated.

## Manuscript Use

Paper-ready:

- Official data provenance and hashes.
- Case E protocol and 80-probe z=2 m validation target.
- Statement that this machine did not yet produce official z=2 m accuracy validation.
- Source-level protocol optimization can be described as an implementation change, not as accuracy proof.

Limitations only:

- Prior Case E error claims unless linked to inspected artifacts.
- Any z+4.5 m diagnostic result.
- Any statement of predictive accuracy, LES improvement, or mesh independence.
