# CityLBM v0.4.0-rc82

## Status

This is an accuracy-diagnostic release candidate, not a formal v0.4.0 release.

Formal `v0.4.0` remains blocked because the official AIJ Case E z=2 m gate is still negative: MAE = 21.111 pp, R2 = -2.006330, Pearson = 0.115756.

## Added

- Added default-off native C016 residual-target code generation to `generate_native_casee.py`.
- Added native options `--residual-target-mode none|c014_channel_response` and `--residual-target-scale`.
- Added `casee_c016_codegen_gate.py` to verify that the C016 path uses pre-registered coordinate-region channel-response logic, records no-fitting manifest fields, and remains blocked from default accuracy promotion.
- Integrated the C016 gate into the reproducibility suite, artifact index, release asset manifest, paper evidence gate, and software-feedback matrix as SF058.

## Experiment Planning

- Updated the candidate sweep so C016 no longer depends on `residual_targeted_wall_inlet_channel_response_not_implemented`.
- Added R010 to the next experiment runbook as a concrete no-SGS AF-k inlet plus C016 channel-response follow-up command.
- Kept C016 blocked until GPU/runtime readiness, official preflight, leakage guard, and codegen gate all pass.

## Boundaries

- This rc does not run FluidX3D.
- This rc does not update official z=2 m metrics or improve R2.
- This rc does not fit RS_caseE official probe targets, apply post-hoc affine calibration, or use official validation probes as training data.
- This rc does not promote residual-target, inlet, no-SGS, wall, or any diagnostic switch to the default precision model.
- This rc does not support predictive-accuracy, mesh-independence, LES-improvement, or formal `v0.4.0` claims.
