# CityLBM v0.4.0-rc30

## Status

CityLBM `v0.4.0-rc30` is an accuracy-diagnostic and Grasshopper claim-gate release candidate. Formal `v0.4.0` remains blocked.

## Added

- `Run Simulation` now exposes a `Claim Gate` (`Gate`) output.
- The output sits beside `Manifest Path` and reports the formal accuracy boundary directly in Grasshopper.
- `citylbm_manifest_output_gate.py` verifies that the new output exists and is set in generate-only, deploy-only, full-auto, background, no-run, running, cancelled, and failure states.
- `casee_default_policy_gate.py` verifies that the new output is a traceability/default-policy feature, not a diagnostic default promotion.
- `citylbm_software_feedback_matrix.py` adds SF013 for the Grasshopper claim-boundary output.

## Claim Boundary

For AIJ Case E runs, `Claim Gate` states that the formal contract is:

- condition `ac`
- wind direction `N`
- wind vector `(0, -1, 0)`
- official z = 2 m
- 80 probes
- `raw_trilinear` only
- diagnostic sampling and z offsets are limitations-only
- formal `v0.4.0` requires `release_gate.json`, Case A smoke regression, Rhino/Grasshopper new-GHA load verification, MAE improvement, positive R2, and positive Pearson

This makes the difference between workflow success and benchmark-accuracy success visible in the plugin UI.

## Not Allowed

- Do not create the formal `v0.4.0` tag from this evidence.

## Remaining Blockers

- Official z=2 m R2 remains negative.
- Rhino/Grasshopper new-GHA loading is not independently verified.
- GPU runtime recovery is still required before additional long native FluidX3D runs.
- Visual Studio Build Tools 2022 C++ installation remains incomplete on this machine.
