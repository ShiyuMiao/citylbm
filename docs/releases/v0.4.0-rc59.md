# CityLBM v0.4.0-rc59

## Staged GHA identity reconciliation

This release candidate reconciles the candidate Grasshopper plugin artifact
used for downstream loading tests.

- `CityLBM/bin/CityLBM.gha` was synchronized with
  `CityLBM/bin/Release/CityLBM.gha`
- the synchronized GHA was staged into the current user's Grasshopper Libraries
  directory
- the reproducibility suite now re-stages the current tracked GHA after
  build-chain regeneration, avoiding stale Grasshopper-library hashes
- `plugin_identity_gate.py` now reports matching tracked and Release GHA SHA256
- `citylbm_gha_install_audit.py` reports a matching staged GHA
- `rhino_gha_load_gate.py` remains fail-closed because no real Rhino session
  load manifest or screenshot/log evidence has been recorded

The synchronized GHA SHA256 is recorded in
`docs/experiments/casee/results/plugin_identity_gate.json` and
`docs/experiments/casee/results/citylbm_gha_install_audit.json`.

## Boundary

This is a software-delivery traceability enhancement only. It does not prove
Rhino/Grasshopper loaded the plugin, recover GPU runtime, add a new FluidX3D
run, change solver defaults, improve official z=2 m metrics, or permit a
formal `v0.4.0` release.

Formal Case E official z=2 m metrics remain:

- MAE = 21.111 pp
- R2 = -2.006330
- Pearson = 0.115756

Formal `v0.4.0` remains blocked until the official z=2 m metric gate and real
Rhino/Grasshopper new-GHA loading evidence pass.
